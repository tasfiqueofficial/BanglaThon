১.২ কেন ট্রি-ওয়াকিং ইন্টারপ্রেটার (Tree-Walking Interpreter)?

আমরা সরাসরি কোনো বাইটকোড বা অ্যাসেম্বলিতে রূপান্তর না করে Tree-Walking Interpreter Pattern বেছে নিয়েছি। এর প্রধান কারণ:

  • ১০০% প্ল্যাটফর্ম নিরপেক্ষতা: কোনো বাইনারি কম্পাইলেশন বা সি-কম্পাইলার ছাড়া যেকোনো অপারেটিং সিস্টেমে সরাসরি চলে।
  • নিখুঁত এরর ট্র্যাকিং: প্রতিটি এএসটি নোডে সোর্স কোডের লাইন ও কলাম নম্বর সংরক্ষিত থাকায় রিয়েল-টাইম ডিবাগিং অত্যন্ত সহজ হয়।
  • শূন্য ডিপেন্ডেন্সি: কোনো এক্সটার্নাল সি-লাইব্রেরি (LLVM, GCC) পিসিতে থাকার প্রয়োজন হয় না।

২. লেক্সিক্যাল অ্যানালাইসিস ও টোকেনাইজার ইঞ্জিন

২.১ লেক্সারের মূল মেকানিজম (FSM Engine)

lexer.py-এর কাজ হলো কাঁচা সোর্স কোডের অক্ষরের পর অক্ষর পড়ে সেগুলোকে অর্থবহ Token অবজেক্টে পরিণত করা। এটি একটি Deterministic Finite Automaton (DFA)-এর মতো আচরণ করে।

# Token ডেটা স্ট্রাকচার: class Token: def __init__(self, type_, value, line, col): self.type = type_ # e.g., 'KEYWORD', 'NUMBER', 'IDENTIFIER' self.value = value # e.g., 'dhori', 42, 'x' self.line = line # এরর ট্র্যাকিংয়ের জন্য লাইন নম্বর self.col = col # এরর ট্র্যাকিংয়ের জন্য কলাম নম্বর

২.২ লুকঅ্যাহেড পয়েন্টার ও স্টেট ম্যানেজমেন্ট

লেক্সারে ৩টি ইন্টারনাল পয়েন্টার থাকে: pos (বর্তমান ইনডেক্স), line (বর্তমান লাইন), এবং col (বর্তমান কলাম)।

  • advance(): একটি ক্যারেক্টার গ্রহণ করে পরবর্তী পজিশনে যায়।
  • peek(): পজিশন পরিবর্তন না করেই পরবর্তী ক্যারেক্টারটি উঁকি দিয়ে দেখে (১-ক্যারেক্টার লুকঅ্যাহেড — যেমন = এর পর আরেকটি = আছে কিনা তা দেখে == নির্ধারণ করা)।

২.৩ কি-ওয়ার্ড ডিকশনারি ম্যাপিং (O(1) Hash Map)

লেক্সার যখন একটি আইডেন্টিফায়ার পায়, তখন সে একটি হ্যাশম্যাপে চেক করে সেটি কি রিজার্ভড কি-ওয়ার্ড নাকি সাধারণ ভেরিয়েবল:

KEYWORDS = { "dhori": TokenType.DHORI, # Variable declaration "jodi": TokenType.JODI, # If "nahole": TokenType.NAHOLE, # Else "jotokkhon": TokenType.JOTOKKHON, # While "jonno": TokenType.JONNO, # For "kaj": TokenType.KAJ, # Function "ferot": TokenType.FEROT, # Return "dekhao": TokenType.DEKHAO, # Print "talika": TokenType.TALIKA, # Array "thamo": TokenType.THAMO, # Break "cholo": TokenType.CHOLO, # Continue "shotti": TokenType.SHOTTI, # True "mittha": TokenType.MITTHA, # False "khali": TokenType.KHALI, # Null "ebong": TokenType.EBONG, # And "ba": TokenType.BA, # Or "noy": TokenType.NOY # Not }

২.৪ ইউনিকোড ও রোমানাইজড ডুয়েল সাপোর্ট

লেক্সারে ক্যারেক্টার ভ্যালিডেশনে c.isalpha() এবং ইউনিকোড রেঞ্জ \u0980-\u09FF অনুমোদিত। ফলে ইংরেজি অক্ষরে বাংলা (dhori x = 5) এবং সরাসরি বাংলা বর্ণমালায় ভেরিয়েবল (dhori সংখ্যা = ৫) দুটোই নির্বিঘ্নে টোকেনাইজড হয়।

৩.১ ব্যাকাস-নওর ফর্ম (Extended BNF Grammar)

পার্সার টোকেন স্ট্রিমকে গ্রহণ করে ভাষার আনুষ্ঠানিক ব্যাকরণ অনুযায়ী ভ্যালিডেট করে। বাংলাথনের ব্যাকরণ ব্যাকাস-নওর ফর্মে নিচে সংজ্ঞায়িত:

৩.২ অপারেটর প্রিসিডেন্স ক্লাইম্বিং (Precedence Climbing)

গণিতে 2 + 3 * 4-এর মান ১৪ হতে হবে, ২০ নয়। রিকার্সিভ ডিসেন্টে প্রিসিডেন্স সমাধানের কৌশল হলো ফাংশন কলিংয়ের লেয়ারিং। পার্সার প্রথমে কম অগ্রাধিকারযুক্ত অপারেটর (term: + / -) কল করে এবং তার ভেতরে বেশি অগ্রাধিকারযুক্ত অপারেটর (factor: * / /) কল করে।

def term(self): node = self.factor() while self.current_token.type in (PLUS, MINUS): op = self.current_token self.advance() right = self.factor() node = BinaryOpNode(node, op, right) return node

এর ফলে অ্যাবস্ট্রাক্ট সিনট্যাক্স ট্রিতে গুণন নোডটি যোগ নোডের নিচে (ডিপার চাইল্ড হিসেবে) বসে, যা সঠিক গাণিতিক ক্রম নিশ্চিত করে।

৩.৩ এরর হ্যান্ডলিং ও সিনট্যাক্স রিকভারি

কোনো প্রতীক্ষিত টোকেন না পাওয়া গেলে পার্সার তাৎক্ষণিক সুনির্দিষ্ট ParserError থ্রো করে—যাতে লাইন ও কলাম নম্বরসহ উল্লেখ থাকে ঠিক কোথায় কী ভুল হয়েছে (যেমন: Expected ')' after condition)।

৪. এবস্ট্রাক্ট সিনট্যাক্স ট্রি (AST) হায়ারার্কি

৪.১ এএসটি (AST) কী এবং কেন এটি অপরিহার্য?

এএসটি হলো সোর্স কোডের একটি বিমূর্ত হায়ারারকিক্যাল ট্রি রিপ্রেজেন্টেশন। এটি সরাসরি কোড টেক্সটের অপ্রয়োজনীয় ব্র্যাকেট, স্পেস ও সেমিকোলন বর্জন করে কেবল লজিক্যাল স্ট্রাকচার ধারণ করে। বাংলাথনের ast_nodes.py-তে ২২টি স্বতন্ত্র নোড ক্লাস রয়েছে।

৪.২ নোড ট্যাক্সোনমি (Node Hierarchy)

ক্যাটাগরি নোড ক্লাসের নাম ধারণকৃত ফিল্ডসমূহ (Fields) তাৎপর্য
Literals NumberNode, StringNode, BooleanNode, NullNode value, line, col কনস্ট্যান্ট বা অপরিবর্তনশীল প্রিমিটিভ ডেটা
Operations BinaryOpNode, UnaryOpNode left, op, right / op, operand গাণিতিক, তুলনামূলক ও লজিক্যাল অপারেশন
Variables VarDeclNode, AssignNode, IdentifierNode name, expr মেমোরিতে ভেরিয়েবল তৈরি ও মান আপডেট
Control Flow IfNode, WhileNode, ForNode condition, body, else_body শর্ত ও পুনরাবৃত্তিমূলক ব্লকের নিয়ন্ত্রণ
Subroutines FunctionDefNode, CallNode, ReturnNode name, params, body ফাংশন সংজ্ঞা ও প্যারামিটারযুক্ত এক্সেকিউশন
Collections ListNode, IndexNode, IndexAssignNode elements, target, index, value ডাইনামিক অ্যারে মেমোরি ও ইনডেক্স মিউটেশন

৪.৩ একটি বাস্তব স্টেটমেন্টের AST ট্রি চিত্রায়ন

ধরা যাক কোডটি হলো: dhori x = 10 + y * 2

ProgramNode └── VarDeclNode (name='x') └── BinaryOpNode (op='+') ├── NumberNode (value=10) └── BinaryOpNode (op='*') ├── IdentifierNode (name='y') └── NumberNode (value=2)

ইন্টারপ্রেটার যখন এই ট্রির রুট নোড থেকে শুরু করে, তখন সে রিকার্সিভলি নিচের দিকে নামে। আগে y * 2 এর ফলাফল বের করে, তারপর তার সাথে 10 যোগ করে এবং সবশেষে x ভেরিয়েবলে সংরক্ষণ করে।

৫.১ সিম্বল টেবিল ও লেক্সিক্যাল স্কোপিং

ইন্টারপ্রেটারের প্রাণ হলো Environment অবজেক্ট। এটি একটি লেক্সিক্যাল স্কোপড সিম্বল টেবিল (Symbol Table), যা একটি হ্যাশম্যাপ বা ডিকশনারিতে ভেরিয়েবল এবং ফাংশনের রেফারেন্স ধারণ করে।

class Environment: def __init__(self, parent=None): self.values = {} # লোকাল ভেরিয়েবল স্টোরেজ self.parent = parent # এনক্লোজিং (প্যারেন্ট) স্কোপের পয়েন্টার def get(self, name): if name in self.values: return self.values[name] if self.parent: return self.parent.get(name) # প্যারেন্ট স্কোপে সন্ধান raise BanglaRuntimeError(f"'{name}' নামে কোনো variable পাওয়া যায়নি") def set(self, name, value): # ভেরিয়েবল অলরেডি যে স্কোপে আছে সেখানেই আপডেট করবে if name in self.values: self.values[name] = value return if self.parent: self.parent.set(name, value) return raise BanglaRuntimeError(f"অঘোষিত variable '{name}' এ মান রাখা সম্ভব নয়")

৫.২ ফাংশন কল ও ফ্রেম পুশ/পপ

প্রতিবার যখন কোনো ফাংশন কল করা হয়, ইন্টারপ্রেটার বর্তমান এনভায়রনমেন্টকে প্যারেন্ট রেখে একটি নতুন চাইল্ড Environment তৈরি করে। ফাংশনের এক্সিকিউশন শেষ হলে স্বয়ংক্রিয়ভাবে সেই ফ্রেমটি পপ হয়ে যায় এবং পূর্বের এনভায়রনমেন্ট ফিরে আসে। এটি নিখুঁত ভেরিয়েবল আইসোলেশন ও রিকার্শন সমর্থন করে।

৫.৩ কন্ট্রোল ফ্লো সিগন্যাল মেকানিজম (Exception-based Signals)

ট্রি-ওয়াকিং ইন্টারপ্রেটারে লুপের গভীর থেকে thamo (break) বা ফাংশন থেকে ferot (return) কীভাবে কাজ করে? এর জন্য আমরা পাইথনের নিজস্ব এক্সেপশন ফ্রেমওয়ার্ককে সিগন্যালিং বা ইন্টারাপ্ট মেকানিজম হিসেবে ব্যবহার করেছি:

  • BreakSignal(Exception): লুপের ভেতরে এটি থ্রো হয় এবং লুপ হ্যান্ডলার এটি ক্যাচ করে ব্রেক করে।
  • ContinueSignal(Exception): লুপের পরবর্তী ইনক্রিমেন্টে লাফ দেয়।
  • ReturnSignal(Exception): ফাংশন কলের গভীর থেকে রিটার্ন ভ্যালুটি সরাসরি ফাংশন হ্যান্ডলারে ফিরিয়ে নিয়ে আসে।

চিরাচরিত পাইথন ইন্টারপ্রেটারে এএসটি নোড পরিভ্রমণ করতে Dynamic Reflection (getattr(self, f"visit_{type(node).__name__}")) ব্যবহার করা হয়। লক্ষ লক্ষ বার লুপ চলার সময় স্ট্রিং কনক্যাটেনেশন ও ডাইনামিক অ্যাট্রিবিউট লুকআপ প্রচণ্ড ওভারহেড তৈরি করে ইন্টারপ্রেটারকে ধীরগতির করে তোলে।

৬.২ ইঞ্জিনিয়ারিং সলিউশন: প্রি-কম্পিউটেড ডিসপ্যাচ টেবিল

আমরা ইন্টারপ্রেটার শুরুর মুহূর্তেই একটি স্ট্যাটিক ডিকশনারি হ্যাশম্যাপ তৈরি করি, যা প্রতি নোড টাইপকে সরাসরি তার হ্যান্ডলার মেথডের সাথে মেমোরিতে ম্যাপ করে রাখে:

# প্রি-কম্পিউটেড মেথড ডিসপ্যাচ টেবিল: self._dispatch = { NumberNode: self.visit_NumberNode, StringNode: self.visit_StringNode, BinaryOpNode: self.visit_BinaryOpNode, VarDeclNode: self.visit_VarDeclNode, AssignNode: self.visit_AssignNode, IfNode: self.visit_IfNode, WhileNode: self.visit_WhileNode, ForNode: self.visit_ForNode, CallNode: self.visit_CallNode, } # এক্সিকিউশন কল (O(1) Constant Time Lookup): def visit(self, node): handler = self._dispatch.get(type(node)) return handler(node)

উত্তর: লেক্সিং ও পার্সিং ফেজে আমাদের কমপ্লেক্সিটি O(N), যেখানে N হলো মোট টোকেন সংখ্যা। এক্সিকিউশন ফেজে ভেরিয়েবল লুকআপ এবং অ্যাসাইনমেন্টের স্পিড হ্যাশম্যাপের কারণে O(1)। রিকার্সিভ ডিসেন্টে পার্স ট্রি সরাসরি এএসটি-তে রূপান্তরিত হওয়ায় কোনো অতিরিক্ত মেমোরি ওয়েস্ট হয় না।
প্রশ্ন ২: "পাইথনে তো রিকার্শন ডেপথ লিমিট (Recursion Depth Limit) থাকে, সেটা কীভাবে সামলান?"
উত্তর: সাধারণ ব্যবহারের জন্য পাইথনের ডিফল্ট রিকার্শন লিমিট (১০০০) যথেষ্ট। তবে কম্পিটিটিভ প্রোগ্রামিংয়ের জন্য আমরা আমাদের মেইন রানারে sys.setrecursionlimit(50000) সাপোর্ট যুক্ত করেছি। এছাড়া ফেজ-২ রোডম্যাপে আমরা টেইল-কল অপ্টিমাইজেশন (TCO) যুক্ত করছি।
প্রশ্ন ৩: "মেমোরি ম্যানেজমেন্ট বা গার্বেজ কালেকশন (GC) কীভাবে হয়?"
উত্তর: আমাদের ইন্টারপ্রেটার হোস্ট পাইথনের রেফারেন্স কাউন্টিং ও জেনারেশনাল সাইক্লিক গার্বেজ কালেক্টর ব্যবহার করে। যখন কোনো ফাংশন ফ্রেম পপ হয়ে যায়, লোকাল এনভায়রনমেন্টের রেফারেন্স কাউন্ট শূন্য হয়ে মেমোরি সাথে সাথে মুক্ত হয়ে যায়।

৯.২ ফেজ ২ ও ৩ ইঞ্জিনিয়ারিং রোডম্যাপ

পর্যায় (Phase) পরিকল্পিত কারিগরি ফিচার প্রত্যাশিত কার্যক্ষমতা ও প্রভাব
ফেজ ২ (২০২৬ শেষ) Bytecode VM (বাইটকোড ভার্চুয়াল মেশিন):
সোর্স কোড থেকে নিজস্ব কাস্টম অপকোড (Opcode) বাইটকোডে কম্পাইল করা।		 ট্রি-ওয়াকিংয়ের চেয়ে আরও ৫ থেকে ১০ গুণ বেশি গতি বৃদ্ধি পাবে।
ফেজ ৩ (২০২৭ শুরু) WebAssembly (WASM) ব্রাউজার রানটাইম:
কোনো ইনস্টল ছাড়া ব্রাউজারে কোড রান করা।		 মোবাইল ও স্কুল ল্যাবে ১০০% জিরো-ইনস্টলেশন এক্সেসিবিলিটি।
ফেজ ৪ (২০২৭ মাঝামাঝি) Language Server Protocol (LSP):
VS Code-এ বাংলা কি-ওয়ার্ডের জন্য অটো-কমপ্লিশন।		 বাংলায় কোডিংয়ের সময় পূর্ণাঙ্গ আইডিই (IDE) এক্সপেরিয়েন্স।
ফাইনাল টেক্সট ফর জাজেস: বাংলাথন কোনো খেলনা স্ক্রিপ্ট বা র‍্যাপার নয়। এটি আধুনিক কম্পিউটার সায়েন্সের কম্পাইলার থিওরির প্রতিটি নীতি নিখুঁতভাবে মেনে তৈরি করা একটি পূর্ণাঙ্গ, পরীক্ষিত ও টেকসই সফটওয়্যার সিস্টেম।
